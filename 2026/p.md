# 2023 Tuna AI Ops

**프로젝트명**
TunA AI - AI Ops 배치 분석 시스템

**프로젝트 개요**
TunA 수집서버와 Elasticsearch에 저장된 시스템 성능 지표 데이터를 분석하여, 운영자가 이상 징후를 효과적으로 감지할 수 있도록 동적 임계치, 지표 간 상관관계, 임계치 적용 대상 추천 정보를 생성하는 AI Ops 배치 분석 시스템을 설계·개발했습니다.

**역할**
단독 설계 및 개발

**기술 스택**
Python, asyncio/coroutine, Pandas, NumPy, StatsModels, Elasticsearch, REST API, Schedule, Loguru, PyInstaller, Docker/CentOS

**주요 수행 내용**
- TunA AI 프로젝트 전체 구조를 처음부터 설계하고 Python 기반 배치 분석 시스템으로 구현
- TunA 수집서버 API에서 분석 설정을 조회하고, Elasticsearch의 대량 시계열 지표 데이터를 분석 대상으로 수집하는 구조 설계
- Elasticsearch 조회 병목을 줄이기 위해 `asyncio` coroutine 기반 비동기 데이터 수집 로직 구현
- 반복 분석 성능을 고려하여 날짜·지표·오브젝트 단위의 로컬 pickle 캐시 전략 설계
- IQR 기반 이상치 제거 후 평균/표준편차와 sigma 값을 활용한 동적 임계치 계산 로직 구현
- 동일 오브젝트 내 counter 조합별 Pearson 상관계수 계산 및 유의미한 상관 지표쌍 추출 로직 구현
- ANOVA 및 Tukey 사후검정을 활용해 시간대별 패턴이 뚜렷한 동적 임계치 적용 대상 오브젝트 추천 기능 구현
- 분석 결과를 Elasticsearch 결과 인덱스에 upsert하고, 기존 데이터 삭제 및 백업 인덱스 생성까지 포함한 운영 흐름 구현
- 설정 파일, 로그, 스케줄 실행, 단독 실행 파일 배포 구성을 포함해 운영 가능한 형태로 패키징

**성과 및 기여**
- 단순 분석 스크립트가 아닌, 설정 조회부터 데이터 수집, 캐싱, 분석, 결과 저장, 완료 알림까지 이어지는 End-to-End 배치 파이프라인 구축
- 대량 시계열 데이터 처리 과정에서 비동기 수집과 로컬 캐시를 적용하여 반복 조회 비용과 분석 대기 시간을 줄일 수 있는 구조 설계
- 시스템 운영자가 수동으로 판단하던 임계치 설정과 지표 간 연관성 분석을 자동화하여 AI Ops 기반 운영 관리 체계 마련
- 통계 분석 로직을 실제 운영 시스템과 연계 가능한 백엔드/데이터 처리 구조로 구현

**한 줄 요약**
대량 성능 지표 데이터를 기반으로 동적 임계치, 상관관계, 추천 정보를 생성하는 AI Ops 배치 분석 시스템을 처음부터 설계·개발했습니다.

# 2023 TunA CloudWatch

## 프로젝트

### TunA Cloud Agent / `tuna.agent.cloud`

**클라우드 메트릭 수집 에이전트 설계 및 개발**

AWS/GCP 클라우드 리소스와 메트릭을 수집하여 TunA/Scouter 기반 모니터링 서버로 전송하는 클라우드 에이전트를 처음부터 설계하고 개발했습니다. 원격 설정 서버로부터 수집 대상, credential, region, metric configuration을 받아 수집기를 동적으로 생성·중지하며, CloudWatch, Resource Tagging API, EC2, Lambda, MSK, GCP Stackdriver 등 다양한 클라우드 API와 연동했습니다.

특히 AWS CloudWatch `GetMetricData` API의 단일 요청당 metric query 제한을 고려하여, 수집 대상 metric/dimension/stat 조합을 500개 단위로 batching하고 batch 단위 goroutine 병렬 처리를 수행하는 구조를 설계했습니다. 이를 통해 API 제한을 준수하면서도 대량 메트릭 수집 성능을 확보했습니다.

### 담당 역할

- 프로젝트 전체 아키텍처 설계 및 Go 기반 백엔드 에이전트 개발
- 원격 Cloud Configuration 기반 수집기 동적 생성/중지 구조 구현
- AWS CloudWatch metric 수집 로직 및 GetMetricData/GetMetricStatistics 호출 전략 설계
- 요청당 metric query 제한을 고려한 batching, concurrency, WaitGroup 기반 병렬 수집 구조 구현
- AWS 리소스 태그/메타데이터 수집 및 metric-resource 매핑 구조 설계
- UDP 기반 metric/resource pack 전송 queue 및 packet size 제어 로직 구현
- 로컬 API 서버를 통한 credential 검증, configuration reload, 상태 조회 기능 구현
- 운영 설정, heartbeat, retry, logging, trace 옵션 등 에이전트 운영 체계 구현

### 핵심 설계 및 성과

- **API 호출 제한 대응**
  CloudWatch `GetMetricData`의 단일 요청 제한을 고려해 metric query를 500개 단위로 분할하고, batch별 병렬 호출을 수행하도록 설계했습니다.

- **대규모 수집 성능 최적화**
  config, credential, region 단위로 독립적인 clipper worker를 생성하고 goroutine 기반으로 수집을 병렬화했습니다.

- **동적 운영 구조**
  중앙 TunA 서버의 configuration 변경을 감지하여 에이전트 재배포 없이 수집 대상과 수집기를 갱신할 수 있도록 구현했습니다.

- **리소스-메트릭 연계**
  CloudWatch dimension, AWS resource tag, TunA configuration 정보를 조합해 resource id를 생성하고, metric data와 resource metadata를 연결했습니다.

- **안정적인 전송 구조**
  각 수집기가 직접 네트워크 전송을 수행하지 않고, 공통 UDP sender queue를 통해 pack을 모아 전송하도록 설계했습니다. packet size 초과 시 분할 전송도 처리했습니다.

### 기술 스택

`Go`, `AWS SDK for Go v2`, `GCP Cloud Monitoring`, `CloudWatch`, `EC2`, `Lambda`, `MSK`, `Resource Groups Tagging API`, `Goroutine`, `WaitGroup`, `Mutex`, `Channel`, `REST API`, `UDP`, `YAML`, `Scouter/TunA Pack`

### 지원 직무와의 연관성

- 설치/운영 자동화: OpenSearch, MariaDB, PHP, 서비스 등록, 실행/종료, 상태 점검 스크립트와 패키징 작업 수행
- 품질/장애 대응: 500 Error, NullPointerException, OpenSearchStatusException, logrotate 권한 오류, Cloud Agent throttling 등 운영 이슈 분석 및 수정
- 고객지원/문서화: 설치 매뉴얼, REST API/Java 코드/CICD 가이드, 정기 교육자료, 고객사 기술지원 수행
