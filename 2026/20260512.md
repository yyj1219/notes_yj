요약: Analytics CDS View 생성 및 레포트 구현 설명회 4월 30일 목요일 | 모임 | Microsoft Teams

| 질문 | 답변 |
|------|------|
| 큐브/디멘션 없이 인터페이스 뷰만으로도 가능? | 인터페이스뷰를 가지고 구성불가. 디멘젼 뷰로 정의되어서 큐브 형태로 연결되어 Analytical view 구성 권고함 |
| Association만 걸어두고 조회 시 필요한 속성만 가져올 수 있나? | Association은 조회 시점에 필요한 속성만 조인하여 퍼포먼스·유연성 확보. 미리 조인해 필드 모두 끌고 오는 것보다 모델링상 유리 |
| 트랜잭션과 마스터 속성 변경 시 집계 기준? | 큐브에서 디멘션과 Association을 활용하면 최신 마스터 속성 기준(B 조직 등)으로 집계 가능. 원천 팩트를 바꾸지 않음 |
| Analytical Query 필수 요건은? | Analytics.query=true 어노테이션 필요. 보통 큐브/컴포지트 뷰 기반으로 정의하고, OData.publish=true 시 자동 OData 서비스 생성 |
| Fiori 앱(무코드) vs ADT(코드) 차이? | 앱은 빠른 생성과 자동 어노테이션 제공. ADT는 세밀 제어·최적화 가능. 앱으로 만든 후 ADT에서 수동 추가한 어노테이션은 앱에서 재게시 시 덮어씌워질 수 있음 |
| 텍스트/다국어 처리 방법? | 텍스트 뷰를 디멘션에 연결하고 디멘션을 큐브에 연결. 로그인 언어에 맞춘 텍스트, 키/텍스트/롱텍스트 전환, 계층 표시 등 시맨틱 기능 활용 가능. 인터페이스 뷰 직결 시 수동 처리 필요 |
| 권한/가시성 문제(큐브가 안 보임)? | 권한 또는 Release 설정 영향. AO 등 일부 도구는 API State의 “Release” 체크 필요. CBO는 권한 이슈 가능성 높음 |
| 쿼리 브라우저/엑셀 Add-in 한계 및 성능 제약? | 웹은 메모리(약 4GB) 제약, INA 서비스의 셀 제한 초과 시 오류. 설정으로 상향 가능하나 S/4HANA 부하 증가. Drill-down 시 데이터량 급증 시 에러 가능. 엑셀 Add-in은 High Volume Mode 제공 |
| 엑셀 Add-in 저장/공유 방식? | 로컬 저장 또는 SAC 워크북 저장. 리프레시 시 로그인 및 권한 검증 후 데이터 갱신. 웹 오피스에서도 동작하나 매크로는 데스크톱 전용 |
| 표준 공수/개발 난이도? | 모델링(인터페이스/디멘션/큐브)이 핵심 난이도. 쿼리 생성은 비교적 단시간 가능. Fiori Elements 앱은 요구사항에 따라 공수 변동 |
| 모델링 시 주의할 점(Group By/Distinct 등)? | 고비용 연산 최소화, 원천 선집계 권장. 잘못된 CDS는 메모리 급증 및 시스템 부하 유발 가능 |
